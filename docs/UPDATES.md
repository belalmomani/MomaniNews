# التحديث من الإعدادات («البحث عن تحديثات»)

## كيف يعمل
1. أنت تشغّل workflow **Publish APK release** من تبويب Actions (زر Run workflow، وتكتب ملاحظات اختيارية).
2. يبني APK ويُنشئ إصدار GitHub باسم `build-<رقم>` ومعه ملفان: `MomaniNews-<نسخة>.apk` و`.apk.sha256`.
3. في التطبيق: الإعدادات ← **البحث عن تحديثات** ← تنزيل ← تثبيت.

## ضمانات الأمان
- التنزيل من `github.com/belalmomani/MomaniNews/releases/download/` فقط، والتحويلات مسموحة إلى نطاقات GitHub عبر https فقط.
- يُتحقق من بصمة SHA-256 المنشورة، ومن أن الحزمة هي `com.momaninews.app` ورقمها أحدث من المثبّت.
- أندرويد نفسه يرفض التثبيت إن اختلف **توقيع** الـ APK عن التطبيق المثبّت.
- الميزة موجودة في نسخة APK المباشرة (debug) فقط؛ بناء release/Google Play لا يحويها ولا إذن التثبيت.

## شروط وتنبيهات صريحة
- **المستودع يجب أن يكون عاماً (Public)** وإلا لن يستطيع التطبيق قراءة الإصدارات.
- مفتاح توقيع debug **موجود علناً في المستودع**؛ أي شخص يستطيع نظرياً توقيع APK بنفس التوقيع. حماية التحديث الحالية إذن هي: مصدر GitHub الخاص بك + البصمة، وليست سرية المفتاح. إن كان الأمان أولوية: انتقل لمفتاح إصدار خاص (docs/RELEASE.md)، وسيحتاج المستخدمون لإعادة تثبيت مرة واحدة، وأضف البصمة SHA-1 الجديدة لـ Google Sign-In.
- النسخ المثبّتة حالياً رقمها 1، فأول إصدار منشور (رقم ≥ 101) سيظهر لهم كتحديث.
- لم تُجرَّب عملية التنزيل والتثبيت على جهاز حقيقي؛ المختبر فقط منطق التحقق (UpdateLogicTest).
