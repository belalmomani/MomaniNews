# إعداد Supabase (طبقة قاعدة البيانات)

## ما الذي تفعله أنت (مرة واحدة، مجاني، بدون بطاقة)

1. أنشئ حساباً على https://supabase.com ثم **New project**. اختر أي اسم، وكلمة مرور قوية للقاعدة (احفظها عندك فقط، **لا ترسلها لي**)، وأقرب منطقة (مثلاً Frankfurt).
2. افتح **SQL Editor → New query**، والصق محتوى الملف `supabase/migrations/20261015120000_initial_schema.sql` كاملاً، ثم **Run**. يجب أن تظهر "Success". (الملف كله معاملة واحدة: إما ينجح كله أو لا يتغير شيء.)
3. **تشغيل الاختبارات (اختياري لكن موصى به):** في استعلام جديد الصق `supabase/tests/rls_tests.sql` ثم Run. النتيجة الصحيحة تظهر كـ **"خطأ"** بهذا النص: `RLS TESTS PASSED: 177 checks`. هذا مقصود: الخطأ يُلغي كل بيانات الاختبار فلا يبقى أي أثر. إن ظهر `RLS TESTS FAILED` فأرسل لي النص كاملاً. شغّله على المشروع الجديد الفارغ فقط.
4. **تسجيل الدخول بـ Google:** Authentication → Providers → Google → فعّله. تحتاج من Google Cloud Console: OAuth Client من نوع **Web** (Client ID وSecret يوضعان في Supabase)، وClient من نوع **Android** (باسم الحزمة `com.momaninews.app` وبصمة SHA-1 للتوقيع). في خانة Client IDs في Supabase ضع Web ثم Android مفصولين بفاصلة. سأرشدك لتفاصيلها عند دمج التطبيق.
5. **أول أدمن:** سجّل دخولك مرة واحدة (بعد دمج التطبيق، أو من Authentication → Users → Add user). ثم في SQL Editor:
   ```sql
   update public.users set role = 'admin' where email = 'بريدك@gmail.com';
   ```
   هذا السطر الوحيد الذي يمنح أدمن؛ لا يستطيع أي مستخدم عبر التطبيق رفع دوره.

## ما الذي أحتاجه منك للدفعة التالية (دمج التطبيق)

أرسل **فقط**: Project URL و **anon (publishable) key** من Settings → API. المفتاحان عامان بطبيعتهما وسيكونان داخل التطبيق، والأمان قائم على سياسات RLS.
**لا ترسل أبداً** مفتاح `service_role` ولا كلمة مرور القاعدة.

## ملاحظات مهمة

- **الإيقاف عند الخمول:** المشاريع المجانية تُوقَف بعد أسبوع بلا نشاط (تُستأنف يدوياً). إن كان التطبيق سيُستخدم باستمرار فلن يحدث ذلك غالباً. الترقية (Pro) مدفوعة ولن تتم دون موافقتك.
- **قرارات مفتوحة (افتراضاتي الحالية):** (أ) من يحق له التصويت والتعليق: أي مستخدم مسجّل غير محظور (لقصرها على الموثّقين غيّر دالة `can_interact` كما في تعليقها). (ب) التعليقات تُنشر مباشرة ويُخفيها الأدمن لاحقاً (مراجعة لاحقة وليست مسبقة).
- **جداول أُضيفت على الـ 11:** `regions` (مناطق قابلة للإضافة) و`news_keywords` (يغلق ثغرة ربط الكلمات المفتاحية بالأخبار).
- **حد التعليقات:** تعليق واحد كل 10 ثوانٍ لكل مستخدم، وحد أقصى 5 طلبات إعلان معلّقة لكل مستخدم.
- **صور التوثيق:** في حاوية تخزين خاصة `verification-docs` (5MB، jpeg/png/webp)؛ يرفع المستخدم إلى مجلده فقط والأدمن وحده يقرأ ملفات غيره.
- **البحث النصي:** إعداد `simple` بلا تجذير عربي؛ لا يوحّد الهمزات (أ/ا) ولا يتجاهل التشكيل بعد. تحسينه لاحقاً.

## ما اختُبر وما لم يُختبر

- **اختُبر:** المخطط وسياسات RLS و177 فحصاً على PostgreSQL 16 حقيقي محلي (زائر/مستخدم/محظور/أدمن/service_role)، وتأكدتُ أن الاختبارات تفشل فعلاً عند كسر صلاحية عمداً.
- **لم يُختبر:** التشغيل على Supabase الفعلي (الاختبار المحلي يحاكي مخططي `auth` و`storage` بنسخة مبسّطة، وإصدار Postgres يختلف)، وجداول التخزين الحقيقية، وإنشاء المستخدم عبر Google فعلياً. لذلك الخطوة 3 هي الفحص الحقيقي؛ أرسل لي نتيجتها.

تشغيل الاختبارات المحلية (تحتاج PostgreSQL 16): `bash supabase/tests/run_local.sh`

## ربط التصويت والتعليقات (التطبيق)

عند تفعيل الدخول الحقيقي يستخدم التطبيق Supabase للتصويت والتعليقات: العدّادات من العرض `news_vote_counts`، والتعليقات من `comments_public`، والكتابة بالرمز الشخصي للمستخدم. صوت واحد لكل مستخدم يفرضه المفتاح الأساسي في القاعدة (لا الكود). تعديل الصوت يتم بـ PATCH ثم إدراج إن لم يوجد؛ **لم يُجرَّب على جهاز بعد**.

## طلب التوثيق (التطبيق)

الملف الشخصي ← «طلب التوثيق»: يكتب المستخدم اسمه ويختار صورة الهوية من منتقي النظام. التطبيق يصغّر الصورة ويعيد ترميزها JPEG (فتُحذف بيانات الموقع)، ويرفعها إلى الحاوية الخاصة `verification-docs/<معرّف المستخدم>/…`، ثم يسجّل الطلب. المدير يراجع من لوحة الأدمن (تبويب طلبات التوثيق). **لم يُجرَّب على جهاز بعد.** إن فشل الإدراج بعد الرفع تبقى صورة يتيمة في الحاوية (لا سياسة حذف للمستخدم عمداً)؛ تنظيفها يدوي من لوحة Supabase → Storage.

## حذف الحساب (مطلوب لـ Google Play)

ملف `supabase/migrations/20261017120000_delete_my_account.sql` يضيف الدالة `delete_my_account()`: تحذف حساب المستخدم الحالي من `auth.users` فتُحذف بياناته بالتسلسل (تصويتات، تعليقات، طلبات توثيق، إشعارات)، وتبقى إعلاناته بلا مالك. ترفض إذا كان المستدعي هو الأدمن الأخير (حتى لا تبقى اللوحة بلا مشرف). زر «حذف حسابي» في الإعدادات يستدعيها.

**شغّل هذا الملف مرة واحدة** في Supabase → SQL Editor (الصق محتواه ثم Run). اختُبرت على PostgreSQL 16 محلي (8 فحوص جديدة، المجموع 185)؛ لم تُجرَّب على Supabase الفعلي.

## وسائط الأخبار (صور وفيديو)

ملف `supabase/migrations/20261017130000_news_media.sql`: يضيف العمود `news.video_url` وحاوية التخزين العامة `news-media` (JPEG وMP4 فقط، حتى 50MB للملف). الرفع والحذف للأدمن فقط، والقراءة للجميع عبر الرابط العام. **شغّله مرة واحدة** في SQL Editor. اختُبر محلياً (193 فحصاً بعد 8 فحوص جديدة). مساحة التخزين المجانية 1GB، فالفيديوهات الكبيرة تستهلكها بسرعة.

## إشعارات الهاتف
التطبيق يفحص جدول `notifications` كل 15 دقيقة (WorkManager) وعند فتح التطبيق، ويعرض إشعاراً للجديد بعد تسجيل الدخول. هذا ليس Push فورياً. الفوري يتطلب Firebase Cloud Messaging (إعداد خارجي).
